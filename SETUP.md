# Setup on a new machine

This repo holds the Go app and tools and the injected C source (`inject/`). To rebuild the C blob or test on real Dolphins you also need the external pieces below, none of which are committed.

## Required external pieces

### 0. Go
- Go 1.26.2 or newer (the `go` line in `go.mod`; release.yml uses the same file). macOS builds also need the Xcode command-line tools (cgo).

### 1. Dolphin emulator
- Install or extract a Dolphin build (this project was developed against Dolphin 2603 and 2609, x64).
- **Memory:** the patched disc gives the game 48 MB of MEM1 (docs/05 "48 MB MEM1"). Dolphin 2609 and newer size the memory from the disc automatically. On older builds enable Config > Advanced > "Enable Emulated Memory Size Override" with MEM1 = 48 MB, or let the app and `wwdev dolphin2` launch Dolphin for you: they pass the override on the command line for that session only. Save states made with a different memory size do not load. Real hardware is not supported.
- The dev defaults expect Dolphin at `%USERPROFILE%\Desktop\Dolphin-x64` with the patched ISO in its `Roms/` folder. Dolphin's user dir is `<exe dir>/User` only in portable mode (`portable.txt` next to `Dolphin.exe`), otherwise `%APPDATA%\Dolphin Emulator`. Override with `DOLPHIN_EXE` / `ISO_PATH` / `USER_DIR_1` / `USER_DIR_2`, or let the app's Setup find them.

### 2. Wind Waker GZLE01 disc image
- A legally obtained Wind Waker (NTSC-U, GameCube) image, CISO or ISO format.
- Place it in Dolphin's `Roms/` folder.

### 3. devkitPPC + Freighter (for compiling the C injection code)
- Install devkitPro with the devkitPPC package: <https://devkitpro.org/wiki/Getting_Started>
- `build.py` takes the devkitPPC folder from the `DEVKITPPC` environment variable, default `C:\devkitpro\devkitPPC`. The devkitPro installer sets it in MSYS form (`/opt/devkitpro/devkitPPC`); `build.py` reads that prefix as `C:\devkitpro`. Set `DEVKITPPC` to a Windows path if devkitPro is installed elsewhere.
- `pip install freighter` (0.2.4; `build.py` points its hard-coded devkitPPC path at `DEVKITPPC`)

### 4. The Freighter project (now in this repo at `inject/`)
- Layout:
  - `inject/src/core/`, `inject/src/mp/` — the injected C code: the core (hooks, services) and the multiplayer mod (puppets, mini-Links, face sync)
  - `inject/include/` — game type/symbol headers (`wwapi.h`, `mailbox_core.h`, `mailbox_mp.h`)
  - `inject/build.py` — Freighter build script (sets hook address + inject address)
  - `inject/original.dol` — clean WW main.dol from a known-good disc (**local only — not committed**)
  - `inject/patched.dol` — Freighter output (gitignored, regenerated by `build.py`)
  - `inject/build/WWMultiplayer.map` — T2's symbols as a Dolphin map (gitignored; Dolphin: Symbols > Load Other Map File)
- `original.dol` is NOT in git — Nintendo copyrighted bytes. Extract your own from a legitimate disc once and drop it in `inject/`.

### 5. zeldaret/tww decomp (reference only)
- Clone <https://github.com/zeldaret/tww> locally.
- Used for symbol lookups (`config/GZLE01/symbols.txt`) and reading game source for hook-target research.

## End-to-end build pipeline

```bash
# 1. Compile the injection (produces inject/patched.dol)
cd inject && python build.py && cd ..

# 2. Regenerate the blob the patcher embeds (internal/inject/blob.go + blob.stamp)
python scripts/extract_blob.py

# 3. Build the Go side
go build -tags desktop,production -o ww-multiplayer.exe ./cmd/ww-multiplayer   # the app window, as releases build it
# (without the tags you get the CLI/TUI build, and no arguments opens the TUI)
go build -o wwdev.exe ./cmd/wwdev   # the developer tools (dump, dolphin2, mp-local, ...)

# 4. Patch your own vanilla disc (ISO or CISO) with the new blob
./ww-multiplayer.exe patch "<roms>/Wind Waker.ciso" "<roms>/WW_Multiplayer_Patched.iso"

# 5. Restart Dolphin and boot WW_Multiplayer_Patched.iso
#    Make sure NO Patches or Gecko Codes are enabled — they fight the DOL.
#    Save states taken on an older blob no longer match it (recapture them).

./wwdev.exe dump              # read the mailbox the patched DOL publishes
./ww-multiplayer.exe debug    # read Link's position for 5 seconds
```

On macOS, `scripts/build-mac.sh` builds `WW Multiplayer.app` and its zip
the way releases do, and `scripts/setup-mac-dolphin.sh` makes the
re-signed Dolphin copy the memory reader needs.

## Bundled Dolphin cheat pack (optional, for testing)

`cheats/GZLE01.ini` ships a curated set of gameplay Gecko codes
(invincible, max rupees, moon jump, walk through walls, super speed, no
small/boss keys, etc.) sourced from gamemasterplc and the gc-forever
WW thread. When you run `./wwdev.exe dolphin2` (wwdev is the developer
tools, built above; releases don't ship it), it
drops this file into `<USER_DIR>/GameSettings/GZLE01.ini` for **both**
Dolphin instances *only if* no GZLE01.ini exists there yet — your own
edits to either user dir are never overwritten.

Nothing is enabled by default. Enable individual codes via Dolphin →
right-click WW in the game list → **Properties** → **Gecko Codes** →
tick the ones you want.

> Caveat: the legacy code-injection workflow used Gecko C2 hooks *to
> install the mod*. The codes in this pack are gameplay-only and don't
> touch our in-DOL patch sites at `0x80006338`, `0x80023204`,
> `0x80108210`, `0x802C39A0`, the OSInit immediates at
> `0x80301818`-`0x80301838`, or `0x80410000+`, so they coexist with the
> patched ISO.

## Testing one-click updates

The app's update check and installer (`internal/update`) never need
GitHub: point `WW_UPDATE_URL` at a fake release server on 127.0.0.1 that
serves a "latest" JSON (`tag_name`, `html_url`, `assets` with
`browser_download_url`), a test exe built with
`-ldflags "-X main.version=v9.9.9"` and a matching `SHA256SUMS`. Run the
app only from a copy of an exe built with an older `-X main.version` in a
temp folder, with `APPDATA` and `LOCALAPPDATA` set to temp folders too:
Update replaces the exe it runs from. A local build (`dev`) never checks.
The test exe must print `ww-multiplayer v9.9.9` for `version` (the
installer runs it once before the old app closes, and puts the old exe
back if it doesn't).
